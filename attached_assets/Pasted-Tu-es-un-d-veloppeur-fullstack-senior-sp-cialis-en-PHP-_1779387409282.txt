## KYC — VÉRIFICATION D'IDENTITÉ
> Obligatoire avant tout retrait. L'utilisateur peut créer des cagnottes et recevoir des dons sans KYC.
### Formulaire KYC (dans dashboard utilisateur)
L'utilisateur doit uploader :
1. Photo **recto** de la carte d'identité nationale
2. Photo **verso** de la carte d'identité nationale
3. **Selfie** tenant la carte en main
### Règles d'upload
- Formats acceptés : JPG, PNG, PDF
- Taille max par fichier : 5 Mo

### Statuts KYC
- `pending` (en attente) — état par défaut après soumission
- `approved` (validé) — par l'admin
- `rejected` (refusé) — par l'admin avec motif obligatoire
## 💰 WALLET UTILISATEUR
Chaque utilisateur possède un portefeuille virtuel avec deux soldes distincts :

| Solde | Logique |
|---|---|
| `balance_pending` | Don reçu, paiement non encore confirmé |
| `balance_available` | Paiement confirmé, disponible pour retrait |

**Logique de crédit :**
1. Don initié → `balance_pending += montant`
2. Paiement confirmé par API → `balance_pending -= montant` + `balance_available += montant`
3. Retrait validé → `balance_available -= (montant + commission)`

## 💳 PAIEMENTS — INTÉGRATION ASHTECHPAY
### Méthodes supportées
1. **Mobile Money** (MTN, Orange, Wave, etc.) via API Ashtechpay
Après validation du formulaire de don et initiation du paiement via l'API :
- Afficher un compteur dégressif de 8 minutes (08:00 → 00:00) indiquant à l'utilisateur qu'il dispose de ce délai pour valider sa transaction sur son téléphone.
- Simultanément, lancer une boucle de polling automatique qui interroge le statut de la transaction toutes les 3 secondes via le webhook/endpoint de l'API de paiement.
- Dès que le statut retourné passe à "validé" :
  * Mettre à jour le statut dans la base de données (côté admin ET côté utilisateur)
  * Arrêter le polling
  * Rediriger automatiquement vers la PAGE DE REMERCIEMENT
- Si le statut passe à "échoué" ou si le délai de 8 minutes expire sans confirmation :
  * Afficher un message d'erreur clair
  * Mettre le statut à "échoué" dans la base de données
  * Permettre à l'utilisateur de réessayer
- Ce mécanisme doit fonctionner entièrement de manière automatique, sans action manuelle de l'utilisateur.
2. **Carte bancaire**  si l’utilisateur veut payer par carte bancaire par exemple Euro ou Dollar Contacter le createur de la cagnotte directement via son numero Whatsapp apres avoir rempli le formulaire

## 🏧 RETRAITS ### 
Processus utilisateur
 1. Vérification KYC `approved` (sinon blocage avec message explicatif) 
2. Vérification `balance_available >= montant demandé` 
3. Formulaire : montant souhaité + moyen de réception (numéro Mobile Money) 
4. Affichage en temps réel : montant brut, commission 10%, montant net reçu 
5. Confirmation → création demande statut `pending`

### Processus admin 
Un fois la demande de retrait envoyee par l’utilisateur, l’admin peut valider le retrait ou non 
Si il valide le retrait de l’utilisateur, le statut change sur la page admin , dans la bd, sur la page utilisateur aussi ,….  Et si il Refuse → motif obligatoire + remise du solde.
